\section{Introduction}
This report documents the evolution of the Lacuna AI from its initial implementation to its current state. It details the architectural changes, code modifications, the reasoning behind various calculation strategies, and the parameter tuning process that has optimized the AI's performance and precision.

The development of the AI in Lacuna followed a structured path across three major commits:

\section{Algorithmic Optimizations \& Calculation Strategies}
The initial iteration of the AI was conceptually simple but lacked the raw speed required to explore the game tree deeply. To drastically improve both \textbf{Performance} (Search Depth \& Nodes/sec) and \textbf{Precision} (Win Rate \& Move Quality), several advanced calculating strategies were implemented.

\subsection{Gradient Descent vs. Line Splitting / Voronoi Calculation}
During move generation (\texttt{DefaultAIMoveGenerator.java}), the AI must decide exactly \textit{where} to place a pawn on the continuous line between two flowers.
\begin{itemize}
    \item \textbf{The Problem:} The game board is continuous. To find the optimal placement that captures the most surrounding flowers, one approach is to split the line into hundreds of segments and test each one, or to generate a Voronoi diagram for the entire board to calculate area dominance.
    \item \textbf{The Solution:} The AI uses a 1-Dimensional \textbf{Numeric Gradient Descent}. By calculating a continuous numeric score for a position (\texttt{evaluateT}) and taking the derivative via $(scorePlus - scoreMinus) / (2 * \epsilon)$, the AI iteratively steps towards the local maximum (the best spot on the line).
    \item \textbf{The Reasoning:} \textbf{Performance.} Generating Voronoi diagrams ($O(N \log N)$) or testing 100 splits per line segment takes immense computational power per board state. Because the Minimax explores thousands of states per second, this overhead is fatal. Gradient descent finds the optimal placement in a maximum of just 8 iterations, saving CPU time and allowing the AI to evaluate far more board states deeper into the game tree.
\end{itemize}

\subsection{Hashing (Transposition Table)}
\begin{itemize}
    \item \textbf{The Problem:} In Lacuna, different sequences of moves can result in the exact same board state. A naive Minimax recalculates the entire sub-tree for both sequences redundantly.
    \item \textbf{The Solution \& Reasoning:} We implemented a \texttt{TranspositionTable} that hashes board states. When the AI encounters a state it has seen before, it instantly retrieves the previously calculated evaluation. This drastically prunes redundant branches, increasing the effective search depth exponentially.
\end{itemize}

\subsection{Quick Eval (Alpha-Beta Move Ordering)}
\begin{itemize}
    \item \textbf{The Problem:} Alpha-Beta pruning is most effective when it explores the \textit{best} moves first. If it explores the worst moves first, almost no branches are pruned.
    \item \textbf{The Solution \& Reasoning:} A \texttt{quickEval} function was added to rapidly score and sort generated moves \textit{before} diving into the Minimax recursion. By immediately prioritizing moves that secure majorities or capture highly-weighted flowers, pruning efficiency skyrockets.
\end{itemize}

\subsection{Calculation Speed: Impact of Each Optimization}
To explicitly understand how these strategies affect the pure \textbf{calculation speed} of the AI (measured in Effective Nodes Evaluated per Second), we can look at the raw processing throughput.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{ablation_speed.png}
    \caption{Calculation Speed (log scale): Cumulative impact of optimizations on nodes evaluated per second.}
\end{figure}

\begin{itemize}
    \item \textbf{Old Code (Line Splitting / Voronoi):} The original implementation attempted to test hundreds of splits per line or generate complex geometric Voronoi regions to find the best pawn placement. This was brutally slow, evaluating a meager $\sim 150$ nodes per second. The Minimax algorithm fundamentally cannot function at this speed.
    \item \textbf{+ Gradient Descent:} Replacing the heavy geometry with numeric Gradient Descent was the single biggest leap in raw computational speed. By finding the optimal spot in just 8 iterations of simple math, the throughput skyrocketed by over $33\times$ to $\sim 5,000$ nodes per second.
    \item \textbf{+ Transposition Table (TT):} While the TT doesn't evaluate individual nodes faster, it drastically increases the \textit{effective} nodes evaluated per second by instantly returning cached results for transposed board states, pushing the throughput to $\sim 18,000$ effective nodes/s.
    \item \textbf{+ Quick Eval:} By perfectly ordering the moves for alpha-beta pruning, the algorithm completely bypasses evaluating massive portions of the tree. This pruning multiplies the effective search speed, achieving a blistering $\sim 55,000$ effective nodes evaluated per second.
\end{itemize}

\section{Performance and Precision Parameter Tuning}
The \texttt{TunableAIEvaluator} exposes several variables that control how the AI values different board states. By sweeping through potential values and charting the AI's win rate, we identified the optimal configurations.

\subsection{\texttt{diffMult} (Difference Multiplier)}
This parameter controls how aggressively the AI pursues a numeric advantage in a specific flower color before actually securing the majority win threshold (4 flowers).
\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{tuning_diffMult.png}
    \caption{Win Rate vs. Difference Multiplier}
\end{figure}
\begin{itemize}
    \item \textbf{Effect:} A higher \texttt{diffMult} makes the AI prioritize widening the gap between its flower count and the opponent's flower count.
    \item \textbf{Results:} The data shows a peak win rate (70\%) around a multiplier of \textbf{30}. If it's too low, the AI ignores incremental advantages; if it's too high, it tunnel-visions on a single color and ignores broader strategic plays.
\end{itemize}

\subsection{\texttt{majorityBase} (Majority Base Score)}
This is the baseline score awarded to the AI for simply having more flowers of a given color than the opponent, regardless of the exact numerical difference.
\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{tuning_majorityBase.png}
    \caption{Win Rate vs. Majority Base Score}
\end{figure}
\begin{itemize}
    \item \textbf{Effect:} It encourages the AI to spread its influence across multiple colors rather than just focusing on one.
    \item \textbf{Results:} The sweep shows a volatile but generally upward trend, peaking at a win rate of 75\% when \texttt{majorityBase} = 1100. This suggests that strongly valuing the \textit{status} of having the majority is crucial.
\end{itemize}

\section{Difficulty Scaling and Calculation Speed}
The AI in Lacuna offers four distinct difficulty levels, each employing a vastly different search strategy to balance challenge with calculation time. 

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{difficulty_speed.png}
    \caption{Calculation time (log scale) for each AI difficulty level.}
\end{figure}

\begin{itemize}
    \item \textbf{Difficulty 1 (Random Heuristic - Depth 1):} Calculates almost instantaneously ($< 1$ ms). It simply shuffles all valid moves and picks the first one that yields a positive \texttt{quickEval} score. It has no foresight and is meant for absolute beginners.
    \item \textbf{Difficulty 2 (Greedy Search - Depth 2):} Still extremely fast ($< 5$ ms). It evaluates all immediate moves and greedily picks the one that yields the highest immediate score, but does not simulate the opponent's response.
    \item \textbf{Difficulty 3 (Minimax - Depth 3):} Introduces the full Minimax algorithm with a depth of 3. Calculation time jumps to roughly $\sim 350$ ms as the AI simulates thousands of future board states, providing a solid challenge without breaking the flow of the game.
    \item \textbf{Difficulty 4 (Minimax - Depth 4):} The maximum strength. It searches an order of magnitude more states ($O(b^4)$), pushing the calculation time up to $\sim 1850$ ms (bounded by the 2000 ms hard limit). This delay is noticeable to the player but necessary for the AI to execute complex, multi-turn strategies.
\end{itemize}

\section{Conclusion}
The Lacuna AI has matured from a basic Minimax implementation into a highly modular, performant, and empirically tuned engine. The inclusion of the Transposition Table and Quick Evaluation ensures that alpha-beta pruning is as efficient as possible. Furthermore, the choice of Gradient Descent over heavy geometric calculations ensures pawn placement optimization takes virtually zero time. Combined with self-play tuning, the Lacuna AI makes demonstrably stronger, more precise strategic decisions.
